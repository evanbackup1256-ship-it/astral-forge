# Layout specs

Each page gets a spec here before its code changes. The spec covers the focal zone, the zones, the reading order, and the zone geometry at 1920x1080, 1366x768 and 844x390. The numbers come from `python3 tools/layout-verify.py`, which mirrors `planComposition` in `UiCore/layoutEngine.ts`.

## Research basis (applies to every spec)

1. **Absolute zones instead of `UIGridLayout`.** Roblox's grid layouts force uniform cells, and once a `UIGridLayout` is inserted it overrides the Size and Position of every sibling ([Creator Hub: Grid and table layouts](https://create.roblox.com/docs/ui/grid-table-layouts)). A page that mixes a hero, a rail and a card wall needs different cell sizes, so pages are composed from absolute zones computed in one pass (`planComposition`). Uniform card walls inside a zone can still use grids.
2. **Fill leftover space instead of leaving gaps.** The UIListLayout flex release says layouts should grow on desktop and shrink on mobile so one UI "looks amazing everywhere" ([DevForum: Flex Features for UIListLayout](https://devforum.roblox.com/t/new-uilistlayout-flex-features-beta/2694081)). The same docs warn that flex costs extra work on every resize ([UIListLayout](https://create.roblox.com/docs/reference/engine/classes/UIListLayout)). The composer copies flex Fill without that cost: the shorter split column's last block, and every tile row, stretch to the band height ([UIFlexItem Fill = 1:1 grow/shrink](https://create.roblox.com/docs/reference/engine/classes/UIFlexItem)).
3. **Use offset sizing and minimum sizes.** The DevForum guide on scaling for all devices warns against scale-only sizing. It recommends UISizeConstraint minimums and offset sizing so touch targets do not collapse on phones ([Scaling UI For All Devices](https://devforum.roblox.com/t/scaling-ui-for-all-devices/1557833); [auto-sizing scrolling frames](https://devforum.roblox.com/t/how-to-create-scrolling-frames-that-automatically-size-correctly/1599960)). Zones are in offset pixels from the measured content width, and every zone keeps a minimum height of 40 px or more, which the verifier checks.
4. **Virtualise long lists and keep row state external.** Long lists stay virtualised (VirtualGrid), following the react-lua virtualized-list guidance to render only a window and keep row state outside the rows ([jsdotlua/virtualized-list-lua](https://github.com/jsdotlua/virtualized-list-lua); [Roblox staff: React + Roblox](https://devforum.roblox.com/t/how-to-react-roblox/2964543)).
5. **Simulator conventions** (Pet Simulator 99, Anime Defenders style): one big focal "now" panel at the top, uniform card walls of at least 3–4 columns on desktop, stats as a compact strip rather than a tall rail, and nothing on the first screen that is not actionable. I could not check these against live screenshots, so they are design conventions, not measured facts.

Viewport math (CoreKit/mobileLayout.ts) gives these content widths:
- 1920 desktop: 1920 − 268 nav − 2×20 padding = **1612**
- 1366 desktop: **1058**
- 844x390 phone landscape: 844 − 2×47 notch side inset − 2×10 padding = **730**. This is the stacked layout. The app ScreenGui uses CoreUISafeInsets, so the live height is 390 − 44 (Roblox's top bar) = 346. After the app top bar and the tab bar, that leaves a content budget of about **219 px** above the fold (forge-ui-2 pass 2, P2.4; Notched Screen Support https://devforum.roblox.com/t/notched-screen-support-full-release/2074324; Experience Controls 44px top bar https://devforum.roblox.com/t/get-ready-for-updated-experience-controls/3163001).
